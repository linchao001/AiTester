## 背景与概念澄清

- 本专项把 :144 的挂起项收敛为**委派式子智能体**（agents-as-tools）：主智能体调 `task` 工具跑子智能体，子只回摘要、控制权不转移。**接力式 handoff**（控制权整体移交）仍为后续独立特性，本期不做——它与「会话强绑定单个智能体」的既定模型冲突，需要会话间接层。
- 业界形态点名（2026-10-05 调研）：Claude Code Task 子智能体（独立上下文、只回最终摘要、description 驱动自动委派）；OpenAI Agents SDK `agents-as-tools`（对比 handoffs=控制转移）；Anthropic orchestrator-worker（并行子、~15× token、紧耦合/写任务明确不适用）；Cognition 调和口径（**写单线程、读可并行**）；LangGraph subgraph-as-tool（interrupt 冒泡到顶、按命名空间嵌套流式）。本仓落点 = **LangGraph 子图作工具**，技术栈零新增（用户确认的前提，见裁定 1）。
- 边界：本专项只做**机制骨架 + 一个通用子智能体**，不建专属人格（裁定 2）。

## 用户裁定（2026-10-05，逐条确认）

1. **形态 = 委派式，纯 LangGraph 实现**，技术栈清晰统一：子智能体 = 一张普通 LangChain 工具（`task`），工具内 invoke 一个与 `build_agent_graph` **同构**的 LangGraph 子图（agent→gate→tools），运行期复用同一套 checkpointer / interrupt / custom 帧 / 三档判定。无第二 runtime、无子进程。
2. **首批 = 仅机制骨架 + 通用子智能体**（`general-purpose`），不做专属子智能体人格。
3. **触发 = 自动 + 显式**：自动=模型按子智能体 description 自判委派；显式=用户点名时必须委派。
4. **审批 = 沿用三档 chip**，不新增「派发」审批墙；严格档下子内写/命令照常逐条挂起；成本靠透明化（名称/状态/耗时/工具数展示）。
5. **默认工具面 = 只读调查四件**：`read / grep_search / glob_search / web_search`（网页搜索已在面内）；**命令执行（pwsh/bash）与写（write/edit）不进默认面**——子智能体是调查员角色，命令是「影响范围静态不可判」的通配能力（第 5 片三档表定性），并行子同时执行会互踩；执行类能力留给执行类子智能体按定义声明。业界惯例：Claude Code Explore/Plan 子智能体只读、Qwen Code 调查员强制只读、Cognition 调和「读并行、写/通配单线程」。**这条默认面同时是裁定 7 并行的大门**：只读面 ⇒ 该子可并行；用户在设置页给它勾上写 / 命令 / 知识库写，该子即自动退回「一轮一个」（设置页 hint 明说这个因果，开关在用户手里，不是服务端暗设的墙）。
6. **设置可调 = 开放**：子智能体的工具/模型进能力配置面——设置·智能体配置 增一行「通用子智能体（被派发用）」，用户可随时勾/取消工具、设默认模型；**仍不进项目清单、不进聊天页直选**（配置面可见 ≠ 直选面可见）。
7. **唤起 = 全靠提示词，三路；并发 = 真并行**（2026-10-05 追加裁定，覆盖早稿「单批单子」的串行形态）：
   - 隐式：模型按 `task` description + 名册自判该派就派；
   - 显式：用户点名子智能体、或下「让子智能体去查 ×××」这类指令时必须真的调 `task`；
   - 并行：用户要求「同时 / 分别查」多件互不相干的调查时，一轮内发多条 `task`，让它们并行跑；有依赖就分轮串行。
   - **不加控件**：无 @ 选择器、无「强制派发」开关（非本期口径不变）；唤起全靠 `case_design` 提示词的「委派」段（逐字钉测）+ 工具 description。
   - **并行的边界由工具面决定，不由服务端猜**：批内每个 `task` 点名的子智能体都**不可挂起**（面内无 write/edit、pwsh/bash、save_to_knowledge）才整批放开并行；只要有一个会挂起，整批退回「一轮一个」。理由见 §5。

## 设计

### 1. `task` 工具（新内置，TOOL_CATALOG 十件 → 十一件）

- 新增 `adapters/tools/subagent_tools/`，仿 `kb_tools` 注入模式：`build_default_registry` 增可选参数（不传则不注册，同 `kb=None` 先例，`adapters/tools/__init__.py:19-46`）。
- 入参（模型侧英文）：`description`（任务简报，**自含**背景/目标/输出要求——子不继承主会话历史）；`subagent_type`（本期仅 `general-purpose`；未知值 → 英文错误文本回模型自纠）；`title`（可选短标题，供 UI 卡）。
- 工具 description **按请求装配注入当前子智能体名册**（名 + description），对齐 Claude Code 的委派发现机制；并在其中写清并行规则（多件互不相干的调查可在同一批发多条 `task` 并行，前提是所点子智能体为只读面），这是模型侧唯一的并行说明书。
- 执行：按子定义经同一 `build_agent_graph` 装配子图 → `invoke`（透传 config；**沿用父 `thread_id`，并行子各占派生 `checkpoint_ns = 父ns@sub.{call_id}`**，理由与门禁见 §5）→ 返回子最终回复文本（单条摘要）作为 ToolMessage。
- 失败语义：子图异常/超时 → 结构化**英文**错误文本回模型，主线程继续；不中断主 run（agents-as-tools 语义）。
- 携带：`case_design` 默认工具面增 `task`；`kb_assistant` **不携带**（平台智能体无语义对象，/kb 链路零变化）。存量本机 `capability_config.json` 的激活路径同 web_search 先例：设置·工具 启用 → 智能体配置 勾选。
- 三档判定表（`auth_rules.py`）的**档位语义不动**：`task` 天然不挂审批（裁定 4）。该文件只新增一份从既有三组 id 派生的集合 `SUSPENDABLE_IDS` 与纯函数 `face_can_suspend()`（并行安全的单一真相，不新增危险度字段、不新增档）。

### 2. 子智能体定义（复用 AgentSpec）

- `agents/catalog.py` 增 `general-purpose`：UI 名「通用子智能体」（中文）、description（模型可见）**英文**——写清适用场景（可并行的调查/读取类任务）与边界（不并行写；重产出走文件、只回摘要）。
- `agents/prompts/general-purpose.md`：人格提示词 + **摘要契约**（结构化 Markdown：目标/发现/结论/产物路径，软上限 ≈2K token）。
- 默认工具面 = 只读调查四件 `read / grep_search / glob_search / web_search`（裁定 5；**不是墙**——声明式白名单按定义改一行即扩，gate 三档对子内调用与主会话同一条判据）。
- 模型与工具**进能力配置面**（裁定 6）：`capability_config` 的 per-agent `default_uid` / `tool_ids` 对子智能体同样生效，缺省模型跟随全局默认；设置·智能体配置 增一行「通用子智能体（被派发用）」供勾选。
- 清单拓扑：catalog 需区分「可直选智能体」（项目清单 / 聊天页下拉消费）与「被派发子智能体」（设置·智能体配置 + 能力配置消费）两个来源；子智能体**不进前者的任何消费面**——避免与「切智能体=切会话」语义打架，只在后者可见可配。
- **深度 1**：`general-purpose` 工具面不含 `task` → 不可递归（声明式表达，非墙）。

### 3. 触发（三路，全靠提示词）

- 隐式（自动）：`agents/prompts/case_design.md` 增「委派」段落（对齐 Anthropic 委派提示工程：给目标/输出格式/工具与来源/任务边界；规模按复杂度自择；先宽后窄），并写明「需要翻大量文件、检索代码或查网页而只要结论的活，自己判该派就派」。
- 显式（指令）：同段落写明「用户点名子智能体、或下『让子智能体去查 ×××』这类指令时必须真的调用 `task`，不许自己代劳」；`task` 的工具 description 同步给出适用场景。
- 并行（指令）：同段落写明「用户要求『同时 / 分别查』多件事时，一轮里一次发出多个 `task`；一件事要等另一件事的结论就分轮串行」。**这一段是并行语义的唯一宣示口**，能落地的部分是提示词逐字钉测（T6），模型是否真的发多 call 归付费走查。
- 骨架期**不做** @ 选择器、强制派发开关等新 UI 控件（非本期）；并行宽度不设阈值，等于模型这一批发了几条 `task`（见 §5）。

### 4. 上下文契约（隔离与交接）

- 子输入 = 子系统提示词 + 任务简报；**不继承**主会话 messages。
- 子输出 = **单条摘要**；重产出落**项目目录**（若该定义带写工具，经 gate 三档照常判定），主上下文只收摘要 + 产物路径。
- 主上下文表示 = `task` 调用下**一条 ToolMessage**——provider「声明⇔结果」双向配对不变量不变（第 5 片 P9 教训直接适用，`2026-10-04-chat-boundary-auth-design.md:36-38`）。

### 5. 审批、成本与并发

- 子内工具调用走**同一个 gate**：`project_dir` 继承主会话、scoped key 同源、interrupt 冒泡后复用现有 wait 帧 / AuthCard / approve / resume——**零第二套审批**。
- 派发本身不挂审批（裁定 4）。
- 成本透明：子跑在 UI 显示名称/状态/耗时/工具数；token 记账不做（无 per-run token 管线，留后续）。
- **并发（裁定 7）= 扇出条件 + 派生检查点命名空间**：
  - **判据单一真相**：`auth_rules.SUSPENDABLE_IDS`（= write/edit + pwsh/bash + save_to_knowledge）与 `face_can_suspend(tool_ids)`；装配期对名册每个子算一次 `parallel[agent_id]`，同一张表既喂 gate 的批形塑形、也喂 `task._run` 的驱动方式——判定与执行不可能分叉。表里没有的子按串行办。
  - **批形塑形**（`shape_task_batch`，无条件先行，含 free 档）：批内**每个** `task` 点名的子都不可挂起 → 全部 `task` 保留、ToolNode `executor.map` 真并发；只要有一个会挂起（含 `task` 与 write/bash 混合批）→ 只留批内第一个 `task`。被延后的兄弟（含非 `task`）一律合成结构化英文 error 的 ToolMessage，保持 provider「声明⇔结果」配对，等下一轮重发。
  - **为什么只读才并行**：并行子共用父 `thread_id`，各占 `父ns@sub.{call_id}` 的派生命名空间（`call_id` 在超步重放间稳定；分隔符避开 langgraph 保留字 `|` 层级与 `:` 任务 id，故用 `.`——否则 `recast_checkpoint_ns()` 会剥掉 `:` 后缀、两个并行子折成同一个 ns），状态互不可见，且 `drop_thread(run_id)` 天然连子 ns 一起收——**清理链路零新增**。而「挂起后靠位置配对续跑」只在父 ns 上被 P1 实测证过：两个会挂起的子挤同一 ns 会互相顶替 resume 值，所以会挂起的子保持单线程（正对齐 Cognition「读并行、写/通配单线程」）。不依赖任何没测过的 LangGraph 跨 ns resume 路由。
  - **并行上限：本期仍不设硬上限**（控制方口径不变）：宽度=模型这批发几条 `task`，服务端不计数、不设阈值——加一个没测过的上限就是加一条没人要求的墙。成本风险由付费走查观察（裁定 4 的透明化），是否加 3 之类的上限留到有人格子智能体时按实测与成本数据定。

### 6. 流式与 UI（最小形态）

- 子内 custom 帧（call/step）带 `subagent` 标注（`{name, title}`），前端折叠机归入「子智能体卡」；主过程块照常渲染 `task` 行。**帧形以 P1 实测为准，spec 定语义不定字面。**
- **并行可见性**：子卡按 `call_id` 建，因此同批并行的多个子天然是**多张同时运行**的卡，无需前端特判；每个子各自 start/done，互不覆盖。
- 兜底（若 P1 证明子帧不可透传）：只发子级状态帧（跑/完/失败 + 耗时），功能不减、可见性降级。
- `AuthCard` 增「来自子智能体」来源标注一行。
- 停止级联（P2 验证）；落盘语义沿用第 4 片截断痕口径。
- 改动面限定：`client.ts` STREAM_EVENTS 白名单、`streamState.ts` 折叠机、`MessageList.tsx` 步骤块三处，力求最小。

### 7. 落点与既有缝

- `orchestration/graph_registry.py` 图构建器缝：子智能体默认走 react 循环（与主图同构），未来范式不同时经缝注册——本期不用。
- `AgentRuntime.build` 零常驻实例语义不变：子运行时按请求装配、用完即弃；子跑状态只活在本次 run（内存）与产物文件。
- 子跑不写主会话 memory/SessionStore；子状态随主 run 收尾收回——并行子的派生 ns 与父同属一个 `thread_id`，既有 `drop_thread(run_id)` 一个收口点连带收回，**不新增清理路径**。

### 数据流

```
POST /api/chat/send/stream
  → 主图 agent →（模型产出 tool_calls 含 task{description, subagent_type}）
  → gate（task 不在三档表 → 放行；先做批形塑形 `shape_task_batch`：全只读子则多条 task 齐发，含可挂起子则只留第一条、兄弟转延后结果；子内工具各有自己的 gate）
  → tools（ToolNode executor.map 并发）
      └─ task._run → 子图.invoke(简报, config 透传, 父 thread_id + 派生 checkpoint_ns=父ns@sub.{call_id})
            → 子 agent→gate→tools …（子内 interrupt 冒泡 → 顶层 wait 帧）
      ← 子最终摘要 → 一条 ToolMessage（同批多个只读子 ⇒ 多把 `task` 并行、各回一条）
  → 主 agent 读摘要继续 → 收尾落盘（主会话恰 +1 条工具结果）
```

## 错误处理

- 模型侧一律**英文**、UI/API 一律**中文**（沿用文案边界裁定）。
- 未知 `subagent_type` → 英文错误文本（列可用名册）回模型自纠。
- 子执行异常/超时 → 结构化英文错误文本作 ToolMessage，主线程继续；UI 步骤卡标「子智能体失败」（可用「↻ 重试」类既有形态留后续）。
- 主 run 停止且子正在跑 → 取消位生效点由 P2 钉；级联落盘同第 4 片。

## 风险与退路

- **P1 是最大的工程假设**（config 透传下 interrupt 冒泡 + 子帧透传）；不过就停，不硬改——退路见 P1 表。
- **P2 的并行假设 = 派生 ns 是否真隔离**（同 `thread_id` 下两个子互不可见、摘要不串位、帧不串台）；不过的退路：`shape_task_batch` 恒只留第一个 `task`（退回串行，语义降为「一批多轮」），并行诉求转后续专项——**报数由用户定夺，不自行选路继续**。
- 骨架期成本不可见（无上限 + 无记账）：缓解 = P2 观察 + 真机一次种子任务；正式记账随人格化加。**并行把单轮调用数从 1 放大到 N**，所以付费走查（验收 7）是本项目最贵的一项，须单独授权。**2026-10-05 走查当日更新**：用户改口「以后走查都由你全部完成」——付费项由 agent 端到端做完、不再逐项讨授权；不变的边界是用户的 8000 / 5173 进程与 `scripts/dev.ps1` 不得动，走查一律在隔离实例（8010 / 5174）上做。
- 提示词唤起不可断言：假模型只能钉提示词逐字与工具形状，模型是否真按「同时查」发多 call 归付费走查；未过不粉饰。
- 子帧透传不可得 → UI 退兜底形态，不阻塞机制落地。

| # | 偏离 spec 早稿 | 落地与理由 |
|---|------|-----------|
| 1 | 子线程形式：spec 写 `thread_id = {run_id}::sub:{n}`；落地为**同线程 + 派生 `checkpoint_ns`**（R1/R14）：不可挂起的子各占 `父ns@sub.{call_id}`，可挂起的子沿用父 ns | P1b 实测：同线程下子 gate 经 scratchpad 继承吃父 resume 值、审批续跑链成立；另开线程则子挂起与父 resume 断链。并行的子不用挂起，改用派生 ns 隔离——`drop_thread(run_id)` 天然连子 ns 一起收，零新清理口 |
